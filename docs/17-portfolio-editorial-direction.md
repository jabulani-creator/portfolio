# 17 Portfolio — Editorial direction (demonstrate, don’t explain)

**Status:** Active product brief · homepage Phase 1 in code  
**Reference:** Visual storytelling and progressive disclosure (e.g. Riccardo Zanutta) — **architecture only**, not a visual clone.

## Core positioning

> **Don't start with the website. Start with the customer.**  
> I find where digital experiences lose customers — then build what fixes it.

The site should behave like a **mini diagnostic**: problem → evidence → diagnosis → opportunity → solution → outcome.  
Design as **magazine + case study + diagnostic dashboard**, not a consulting report.

## Homepage (movie trailer)

| Order | Section | Job |
|-------|---------|-----|
| 1 | Hero | One promise + two CTAs |
| 2 | The idea | Customer journey line — where it breaks |
| 3 | Businesses investigated | Problem-led case cards (proof) |
| 4 | The diagnostic | Leak types (visual) |
| 5 | The method | Discover → Trace → Diagnose → Fix |
| 6 | What the fix looks like | Not everything is a new website |
| 7 | Mirror pain | “See your business in these?” |
| 8 | About | Short founder line |
| 9 | CTA | Book diagnostic |

**Not on homepage:** full deliverables list, long methodology essays, entire diagnostic report.

## Case study pages (the movie)

- Hero + business context  
- Problem as visual cards (find / understand / book)  
- Journey friction as **screens**, not paragraphs  
- **Revenue leaks** + **the fix**  
- Before → after journey  
- Evidence and build only after curiosity is established  

## Nav

Work · Diagnostics · How I Work · About · Contact + **Book a Diagnostic**

## Later phases

- **Phase 2 (in code):** Diagnostic snapshot, problem triad, journey friction screen, leaks + fix bands, flow-style before/after, collapsible long narratives, work index split (investigations / builds).
- **Phase 3 (in code):** Story layer — hero hook, engines, personas, journey status screen, ranked leaks, fix layers, recommendation, blueprint, outcome table, role strip; **full diagnostic** collapsed at bottom.
- Cross Park case study when slug exists in CMS
- **Experiments** section when content exists
